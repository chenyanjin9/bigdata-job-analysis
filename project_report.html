1. 项目概述

背景。大数据产业持续扩张，但求职者普遍缺乏对市场供需、技能要求与薪酬水平的结构化认知，往往只能凭直觉或碎片信息做决策。与此同时，主流招聘平台（BOSS直聘、智联、前程无忧等）的批量抓取存在合规与法律风险，不宜作为学生作品的采集对象。

目标。本项目以合规公开数据源为对象，构建一条完整的「数据采集 → 清洗预处理 → 探索性分析 → 可视化呈现」数据工程链路，将分散的职位文本转化为可度量的市场洞察，回答「去哪发展、学什么技能、如何定位自身竞争力」三类求职核心问题。它既是一份求职决策辅助，也是对个人大数据技术栈（爬虫、ETL、分析、可视化）的综合实践。

我的角色与产出。作为项目唯一执行者，独立完成需求拆解、采集器编写、数据清洗、EDA 与可视化看板开发，形成可复现、可部署的作品集站点。

2. 数据源与采集方案

2.1 数据源选择原则

优先选择政府公共就业渠道与公开数据集，规避商业招聘平台的 robots 限制、反爬机制与法律判例风险；同时贴合「川渝就业情报」主线，区域样本更聚焦。推荐优先级如下：

优先级数据源说明
★★★中国公共招聘网 job.mohrss.gov.cn人社部官方，合规风险最低
★★★四川 / 重庆公共就业服务网区域聚焦，契合川渝主线
★★☆高校就业指导中心、公共数据开放平台结构化程度较高
★☆☆Kaggle / 天池公开职位数据集适合快速跑通流程验证
✕ 排除BOSS直聘 / 智联 / 前程无忧 / 拉勾robots 禁止、反爬、违反用户协议、有判例风险

2.2 采集字段清单（17 列）

job_id, job_title, company_name, city, district, salary_text, salary_min, salary_max, experience_req, education_req, company_size, industry, skill_tags, job_description, publish_date, source, crawl_time

2.3 采集框架与合规规范

采集器以 requests + BeautifulSoup 为核心，内置 RobotFileParser 遵守 robots 协议、限速器（≥2 秒 + 随机抖动）、429 自动退避、UTF-8-BOM 落盘与去重。核心要点：

  • 守协议：每次采集前读取目标站 robots.txt，仅抓允许路径。
  • 控频率：请求间隔 ≥ 2 秒（政府站建议 3–5 秒），附带真实 UA，避免对服务器造成压力。
  • 懂退避：遇 429 / 503 读取 Retry-After 自动暂停，不强行突破。
  • 守边界：只采集公开职位字段，不触碰个人隐私，不绕过登录/反爬。
  • 可溯源：成果标注来源与「趋势性分析」口径，不宣称精确就业指导。

3. 数据预处理与清洗

清洗使用 pandas 实现，覆盖四类典型问题。演示数据本身较干净，故本批命中 0 异常，但脚本按「真实脏数据」标准编写，可直接复用于真实采集结果。

步骤处理动作本批结果
字段类型转换薪资转数值、日期转 datetime、派生 salary_avg已完成，新增 1 列
缺失值处理关键字段（薪资/职位）缺失→丢弃；分类字段缺失→填「未知」0 行丢弃

清洗后数据：30 行 × 18 列。关键代码（带注释）：

# 1. 类型转换：薪资/日期转可计算类型，并派生月薪均值
df["salary_min"] = pd.to_numeric(df["salary_min"], errors="coerce")
df["salary_max"] = pd.to_numeric(df["salary_max"], errors="coerce")
df["publish_date"] = pd.to_datetime(df["publish_date"], errors="coerce")
df["salary_avg"] = (df["salary_min"] + df["salary_max"]) / 2

# 2. 缺失值：关键字段丢行，分类字段补「未知」
df = df.dropna(subset=["salary_min","salary_max","job_title"])
for col in ["city","education_req","experience_req","industry"]:
    df[col] = df[col].fillna("未知")

# 3. 异常值：薪资必须为正、min<=max、且不超过上限
df = df[(df["salary_min"]>0) & (df["salary_max"]>0) &
        (df["salary_min"]<=df["salary_max"]) & (df["salary_max"]<=200)]

# 4. 去重：优先按 job_id
df = df.drop_duplicates(subset=["job_id"], keep="first")

5. 业务结论与项目价值

结论一 · 地域选择：成都岗位量大（18 个）、机会密集；重庆起薪更高（15.58K > 成都 12.83K）。建议应届生优先布局川渝，重机会量看成都、重起薪看重庆，两地通投扩大命中。
结论二 · 经验门槛：30 岗中「1-3年」占 16 个（主力），「应届/在校」仅 2 个。企业普遍要即战力——必须用 实习 + 课程项目 + 竞赛 把简历填出实战痕迹，否则初筛易被刷。
结论三 · 技能路线：SQL+Hive+Spark 是刚需三件套，Flink/Kafka 代表实时趋势。建议先精通 SQL 与 Hive 数仓建模，再熟用 Spark，有余力补 Flink，切忌一上来贪多求全。
结论四 · 学历焦虑：本科 20 个为招聘主流，但本科均薪（14.2K）不输硕士（13.6K）。学历是门槛而非天花板，专科生把数仓 ETL 项目做透、能讲清技术细节与业务价值，比刷学历标签更有效。
